# EduCapy

EduCapy adalah aplikasi les privat one on one yang mempertemukan murid dengan pengajar. Pengguna bisa mencari profil pengajar, mengatur jadwal les, dan mengelola datanya lewat satu sistem terpusat.

Repo ini dipakai tim untuk mengerjakan proyek secara kolaboratif pada Tugas Besar 2 (eksekusi, monitoring dan pengendalian proyek). Dasar perencanaannya ada di dokumen perencanaan proyek dari Tugas Besar 1.

## Latar belakang

Belajar di kelas sering membuat murid sulit fokus karena jumlah murid yang banyak, lingkungan yang kurang tenang, dan jam belajar yang tidak cocok. Les privat satu pengajar untuk satu murid dinilai lebih efektif untuk menjaga konsentrasi dan mengakomodasi minat khusus murid. EduCapy dibuat sebagai sarana les privat yang fleksibel dalam pemilihan waktu dan tempat.

## Tujuan

1. Menyediakan layanan les privat yang fleksibel dan terstruktur, termasuk penjadwalan antara murid dan guru.
2. Menyusun database terpusat untuk data operasional yang bisa diakses pihak yang punya hak akses.

## Fitur yang direncanakan

- Aplikasi multi-pengguna dengan tiga peran: murid, pengajar, dan admin
- Manajemen hak akses per peran
- Pencarian profil pengajar
- Penjadwalan les
- Pengelolaan data diri pengguna
- Database MySQL terpusat

Daftar lengkap beserta prioritasnya ada di `docs/product-backlog.md`.

## Teknologi

- Back-end: Laravel
- Database: MySQL (dirancang dengan MySQL Workbench)
- ERD: Draw.io
- Desain UI: Figma
- Front-end: mengikuti desain Figma, teknologinya dipastikan di Sprint 3
- Version control: Git dan GitHub
- Manajemen proyek: Trello (papan Kanban)

## Metodologi dan jadwal

Proyek memakai Agile dengan kerangka Scrum. Pekerjaan dibagi menjadi satu tahap inisiasi dan lima sprint.

| Sprint | Fokus | Paket kerja | Durasi | Status |
|---|---|---|---|---|
| 0 | Manajemen proyek dan inisiasi | 1.1, 1.2 | 1 hari | Selesai |
| 1 | Product backlog dan ERD | 2.1, 2.2 | 2 hari | Selesai |
| 2 | Normalisasi dan pemecahan backlog | 3.1, 3.2 | 2 hari | Dikerjakan |
| 3 | UI dan back-end bagian 1 | 4.1 sampai 4.3 | 4 hari | Direncanakan |
| 4 | UI, back-end bagian 2, dan database | 5.1 sampai 5.4 | 4 hari | Direncanakan |
| 5 | Testing dan peluncuran | 6.1 sampai 6.4 | 3 hari | Direncanakan |
